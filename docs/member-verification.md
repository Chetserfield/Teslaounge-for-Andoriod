# 실제 회원 간 검증 · 2026-11-01

서울 프로젝트에서 검증 전용 이메일 회원 두 명으로 실제 Supabase Auth 세션을 발급받아 REST API를 검증했다. 카카오 OAuth를 통과한 것은 아니다. 이메일을 발송하지 않았고 테스트용 인증 데이터만 별도로 준비했다. 서버 관리자 키를 앱/스크립트에 넣지 않고 공개 키와 각 회원의 인증 토큰으로 요청했다.

통과 항목:
- 서로 다른 두 계정의 실제 로그인과 서버 프로필 생성.
- A의 게시글을 B가 조회하고, B의 댓글을 A가 조회.
- B의 A 게시글 수정/삭제 차단, B의 A 프로필 수정 차단.
- A의 B 댓글 수정 차단, 댓글 작성자의 삭제 허용.
- 게스트 게시글/댓글 쓰기 차단, 회원의 관리자 hidden 필드 수정 차단.
- 공감 생성, 중복 차단, 합계 1 확인, 취소 후 합계 0 확인.
- 다른 회원에게 공감자 ID 목록이 노출되지 않음.
- 테스트 글과 댓글 정리 및 두 테스트 세션 로그아웃 요청.

재현 스크립트: backend/smoke.py. 인증정보는 저장소 밖에 임시 보관하며 커밋하지 않는다. 원본 실행 결과는 output/member-verification.txt에 보관한다.

범위: 서버 회원 간 기능 정상. 카카오 제공자 설정 및 실제 카카오 가입, 두 실물 휴대폰 사용 검증은 여전히 별도 작업이다. 공감 집계 함수 보안 advisor 경고 2종과 공개 서비스 운영 준비 항목은 deployment-status.md에 기록돼 있다.

정리 완료: 테스트 Auth 계정 2개 삭제 확인. 테스트 비밀번호 파일도 로컬에서 제거했다.
