# TESLounge Android 0.2

기존 v0.1 Java 네이티브 앱을 복원하고, 서비스 기획안 v0.3의 사용자 유형별 메뉴를 반영한 개발본입니다. 개발용 APK 빌드와 서명 검증을 완료했습니다. 에뮬레이터 검증 결과는 아래에 기록합니다.

## 이번 변경
- MY에서 관심자 / 예비 오너 / 오너 선택 및 기기 내 저장
- 유형별 홈 안내와 5개 하단 탭
- 예비 오너와 오너의 커뮤니티에서 인도 체크리스트 진입
- TradingView TSLA 차트와 뉴스·서비스·내 차의 미연결 안내 화면
- 기존 글쓰기, 검색, 댓글, 공감, 글 삭제, 체크리스트, 닉네임 기능 유지

사용자 유형은 화면 구성에만 사용합니다. 인증과 서버 권한은 아직 없습니다. 모든 작성 내용은 기기에만 저장되고 다른 사용자에게 공유되지 않습니다. TSLA는 TradingView 외부 위젯으로 표시합니다. 뉴스·예약·차량 데이터는 아직 연동하지 않았습니다.

## 빌드 환경
이 작업 폴더의 상위 `.android-tools/`에 JDK 17, Android SDK 35, Build Tools 34.0.0, Gradle 8.9를 설치했습니다. Gradle wrapper와 공식 배포 SHA-256 검증 설정을 포함했습니다.

현재 Mac에서:

```sh
bash scripts/build-local.sh
```

다른 컴퓨터에서는 JDK 17과 SDK 35를 준비하고 `ANDROID_HOME`을 설정하거나 Android Studio에서 SDK 위치를 선택한 뒤 실행합니다.

```sh
./gradlew assembleDebug lintDebug
```

APK 경로: `app/build/outputs/apk/debug/app-debug.apk`. 개발용 디버그 서명이며 스토어 제출용 릴리스 APK는 아닙니다.

테스트 전용 에뮬레이터를 실행한 상태에서:

```sh
bash scripts/build-local.sh connectedDebugAndroidTest
```

이 테스트는 테스트 앱의 로컬 데이터를 초기화하므로 개인 데이터가 있는 실기기에는 실행하지 마세요.

- 실제 휴대폰 검증: 미실행

## 검증할 주요 흐름
1. MY에서 세 유형을 각각 저장하고 홈 안내와 하단 메뉴가 바뀌는지 확인

6. TSLA 차트와 다시 불러오기, 뉴스·예약·차량의 준비 중 안내 확인

## 배포 파일
`output/TESLounge-0.2-debug.apk`를 Android 8.0 이상 기기로 복사해 설치할 수 있습니다. 주식 차트는 인터넷 연결이 필요하며 나머지 작성 데이터는 기기에 저장합니다. Google Play 배포 및 실제 휴대폰 호환성 검증은 하지 않았습니다.

`output/verification.md`에 검증 범위와 제한을 기록했습니다.

## 현재 디자인
차콜 배경, 낮은 곡률의 카드·입력창, 흰색 주요 버튼과 흰색 선택 상태를 사용합니다. 홈은 차량 이미지와 사용자 유형 제목 중심으로 구성하고 단색 선 아이콘을 사용합니다. 시스템 바·선택 메뉴·다이얼로그에도 어두운 테마를 적용했습니다. 차량 일러스트 대신 기존 홈페이지의 차량 이미지를 사용하며 출처는 `docs/image-credits.md`에 기록했습니다. 사진은 연결된 사용자 차량을 뜻하지 않습니다.

## TSLA 차트
TradingView 무료 Symbol Overview 위젯을 검정 테마로 표시합니다. API 키나 별도 백엔드는 필요하지 않습니다. 시세를 추출·저장·재배포하지 않으며 공급자 로고와 링크를 유지합니다. 거래소 통합 실시간 시세를 보장하지 않으며 데이터 기준은 위젯 표시를 따릅니다. 공급자 장애나 네트워크 차단 시 다시 불러오기 또는 외부 브라우저 링크를 이용합니다.

차트 화면을 열면 TradingView로 IP 주소와 위젯 관련 요청 정보가 전달됩니다. 앱의 프로필·게시글은 전달하지 않습니다. WebView는 로컬 파일 접근과 네이티브 JavaScript 브리지를 제공하지 않습니다.

공식 문서: https://www.tradingview.com/widget-docs/widgets/charts/symbol-overview/
데이터 안내: https://www.tradingview.com/widget-docs/faq/data/

## 카카오 가입 진입 화면
공개 화면은 게스트로 볼 수 있으며 글쓰기·공감·댓글 저장 시 가입 화면을 엽니다. 카카오 버튼은 현재 연결 준비 안내를 표시하며 OAuth 요청이나 회원 계정 생성은 하지 않습니다. 사용자 소유 Kakao 앱과 Supabase 프로젝트 설정 후 실제 인증을 연결해야 합니다.

기존 로컬 기능은 가입 화면의 ‘기기에만 저장하며 체험하기’에서 사용할 수 있습니다. MY에서 체험을 종료할 수 있고 일반적인 앱 새 실행은 게스트로 시작합니다(화면 재생성 시에는 체험 상태 유지). 기기에 저장한 글·체크리스트는 삭제되지 않습니다. 로컬 프로필은 회원가입·차량 인증으로 취급하지 않습니다.

구현 범위와 실제 인증 연결 계획: `docs/superpowers/plans/2026-11-01-kakao-entry.md`.

## 업체 탐색과 글자 크기
모든 사용자 유형에서 홈·뉴스/주식·커뮤니티·업체·MY(오너는 내 차)의 5개 메뉴를 사용합니다. 업체 화면에 업체명/지역 검색어 입력, 서비스 종류 선택, 조건 초기화와 별도의 광고 영역을 추가했습니다. 실제 업체 데이터와 광고 공급원은 미연결이므로 현재는 빈 상태만 표시하며 가상의 업체·평점·가격은 넣지 않았습니다.

큰 제목 24sp, 섹션 제목 19sp, 주요 본문 및 버튼 14sp 중심으로 축소했습니다. 작은 보조 문구와 시스템 글꼴 확대 설정은 유지합니다.

## 공유 서버 (설정 후 활성화)
Supabase 데이터베이스 migration, RLS 권한 검증과 Android 카카오 OAuth PKCE/공유 게시판/케어 조회 코드를 추가했습니다. 프로젝트 미생성으로 실제 클라우드 배포는 아직 하지 않았습니다. `backend.local.properties`가 없는 빌드는 기존 로컬 체험으로 동작합니다.

설정 및 검증: [서버 설정 안내](docs/server-setup.md). 공개 운영 준비가 끝난 서비스가 아닌 비공개 테스트용 기반입니다.

## 현재 배포 대상
서울(ap-northeast-2)의 teslounge-seoul 서버에 연결했습니다. [배포 상태와 검증 범위](docs/deployment-status.md)를 참고하세요. 카카오 제공자는 아직 미설정이므로 공유 데이터 조회는 가능하지만 실제 회원가입/게시글 작성은 인증 연결 후 사용할 수 있습니다.

실제 이메일 테스트 회원 두 명의 로그인, 글/댓글 공유, 타인 수정·삭제 차단 및 공감 검증을 통과했습니다. [회원 간 검증](docs/member-verification.md). 카카오 제공자 설정은 별도로 남아 있습니다.
